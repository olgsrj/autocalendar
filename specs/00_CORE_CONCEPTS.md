\# 00\_CORE\_CONCEPTS.md — Общие понятия, Архитектура, Формулы и Конвертер БД



\## 1. Архитектура и стек

\- \*\*Тип приложения:\*\* Автономное Local-First PWA (Vite + Vue 3 Composition API или React 18 + TypeScript + Tailwind CSS + Lucide Icons + Chart.js).

\- \*\*Хранение данных:\*\* Локальная база в браузере/смартфоне на базе `Dexie.js` (`IndexedDB`). Никаких внешних серверов БД не требуется.

\- \*\*Миграция из Excel:\*\* В само PWA-приложение \*\*НЕ встраивается\*\* парсер Excel. Для разовой конвертации файла `Автокалендарь.xlsx` создаётся отдельный Python-скрипт `scripts/convert\_excel\_to\_backup.py`, который генерирует эталонный JSON-файл бэкапа `autocalendar\_initial\_backup.json`. В самом приложении есть только функции «Импорт бэкапа (.json / .zip)» и «Экспорт бэкапа (.json / .zip)».

\## 2. Ключевые сущности и понятия доменной модели



\### 2.1. Автомобиль (`Car`) и Статус владения

Приложение поддерживает несколько автомобилей (Мульти-гараж). У каждого автомобиля есть статус:

\- `status: 'active'` — текущий эксплуатируемый автомобиль.

\- `status: 'sold'` — проданный автомобиль (находится в архиве). Когда выбран проданный автомобиль, его история, аналитика и стоимость владения рассчитываются на интервале от `purchaseDate` до `soldDate` (а не до сегодняшнего дня!).

\- Поля `Car`:

&#x20; - `id`, `name` (напр. `"Chevrolet Lacetti"`), `year` (`2009`), `plateNumber`, `vin`.

&#x20; - `purchaseDate` (`"2020-07-05"`), `purchaseMileage` (`130712`), `purchasePrice` (`360000`), `selectionServiceCost` (услуги подборщиков, `25000`).

&#x20; - `soldDate` (nullable), `soldMileage` (nullable), `soldPrice` (nullable).

&#x20; - `tankVolume` (`60` л — используется для расчёта запаса хода на одном баке).

&#x20; - `manualMileage` (ручная отметка одометра, если пользователь обновил пробег без заправки).



\### 2.2. Глобальные формулы расчёта пробега и экономики (для активного авто)

1\. \*\*Текущий общий пробег (`currentMileage`):\*\*

&#x20;  Вычисляется динамически как максимум среди всех записей данного автомобиля:

&#x20;  `MAX(purchaseMileage, manualMileage, MAX(refuelings.mileage), MAX(serviceEvents.mileage), MAX(parts.installedMileage))`.

2\. \*\*Пробег за время владения (`ownedMileage`):\*\*

&#x20;  `currentMileage - purchaseMileage` (для Lacetti: `203 408 - 130 712 = 72 696 км`).

3\. \*\*Пробег за текущий год (`currentYearMileage`):\*\*

&#x20;  Вычисляется по записям заправок и сервисов:

&#x20;  - Берется максимальный пробег в текущем календарном году (`maxKmThisYear`).

&#x20;  - В качестве стартовой точки года (`startKmThisYear`) берется максимальный зафиксированный пробег на конец предыдущего года (до 31 декабря включительно). Если в предыдущем году записей не было — берется минимальный пробег текущего года или `purchaseMileage`.

&#x20;  - `currentYearMileage = maxKmThisYear - startKmThisYear`.

4\. \*\*Среднемесячный пробег за год и темп езды (`dailyPaceKm`):\*\*

&#x20;  - Среднесуточный темп (`dailyPaceKm`): пробег за последние 180 дней (или с начала года), делённый на количество дней между крайними записями. Используется для прогноза даты следующего ТО.

5\. \*\*Время владения (`ownershipDays`):\*\*

&#x20;  - Для активного авто: количество дней от `purchaseDate` до `TODAY()`.

&#x20;  - Для проданного авто: количество дней от `purchaseDate` до `soldDate`.

6\. \*\*Финансовые показатели:\*\*

&#x20;  - `fuelCostTotal` = сумма `actualCost` всех заправок автомобиля.

&#x20;  - `partsCostTotal` = сумма `totalPrice` всех купленных запчастей (`status === 'installed' || status === 'in\_stock'`; черновики `'wishlist'` без цены не входят).

&#x20;  - `serviceCostTotal` = сумма `totalLaborCost` всех заказ-нарядов.

&#x20;  - `miscCostTotal` = сумма `cost` всех записей из «Разное» + полисы ОСАГО (без дублирования, если полис уже учтён в Разном).

&#x20;  - \*\*Всего на обслуживание (`maintenanceTotal`):\*\* `fuelCostTotal + partsCostTotal + serviceCostTotal + miscCostTotal` (эталон по таблице: `633 261.63 ₽`).

&#x20;  - \*\*Всего потрачено с покупкой (`grandTotal`):\*\* `purchasePrice + selectionServiceCost + maintenanceTotal` (эталон по таблице: `1 018 261.63 ₽`).

&#x20;  - \*\*Стоимость в день:\*\* `maintenanceTotal / ownershipDays` (и отдельно в скобках с учётом покупки).

&#x20;  - \*\*Стоимость в месяц:\*\* `Стоимость в день \* 30`.

&#x20;  - \*\*Стоимость 1 км пробега:\*\* `maintenanceTotal / ownedMileage` (эталон: `8.71 ₽/км`).

&#x20;  - \*\*Доля от дохода (%):\*\* если в глобальных настройках (`appSettings.monthlySalaryNet`) указан доход, считается как `(Стоимость в месяц / monthlySalaryNet) \* 100%`.

\## 3. Спецификация Python-конвертера (`scripts/convert\_excel\_to\_backup.py`)

Скрипт читает `Автокалендарь.xlsx` и формирует JSON-бэкап `autocalendar\_initial\_backup.json` со следующей очисткой:

1\. \*\*Заправки (`Заправки + пробег`, 201 запись):\*\*

&#x20;  - Читать вычисленные значения (`data\_only=True`).

&#x20;  - Запись из строки 145 (`2025-04-01`, пробег `186355`, `49.01 л`, `3072.93 ₽`) исправить на дату \*\*`2025-05-01`\*\*.

&#x20;  - Отсортировать все заправки строго по возрастанию `mileage` (это автоматически исправит порядок двух заправок от `2025-04-26` с пробегами `184556` и `184706`).

&#x20;  - Для каждой заправки вычислить:

&#x20;    - `calculatedCost = round(liters \* stationPrice, 2)` (если указаны литры и цена).

&#x20;    - `actualCost` = значение из колонки «Стоимость».

&#x20;    - `discountAmount = round(calculatedCost - actualCost, 2)` (если разница > 0.5 ₽).

&#x20;    - `effectiveLiterPrice = round(actualCost / liters, 2)`.

&#x20;  - Для последней дозаправки на пробеге `203408` (дельта 48 км, 21 л) выставить `isFullTank = false`, чтобы не искажать расход на главном экране цифрой `43.75 л/100 км`.

2\. \*\*Сервис (`Сервис`, 50 строк -> 27 заказ-нарядов):\*\*

&#x20;  - Сгруппировать строки по ключу `(date, mileage, organization)` в объекты `serviceEvents` со вложенным массивом работ `items`.

&#x20;  - Исправить сбившиеся от автозаполнения адреса сервиса `Slok` (`строение 5..15`) на единый адрес: `г. Москва, ул. Примерная, д. 1`.

3\. \*\*Расходники (`Расходники`, 84 строки):\*\*

&#x20;  - В строках 2–5 заменить формульные ссылки пробега из 2025 года на фактический пробег первого ТО после покупки (`130750 км`).

&#x20;  - Строки 80–85 без даты и цены перенести со статусом `wishlist` («К покупке / Черновик»). Остальные 78 строк — `installed` (привязав к соответствующим `serviceEvents` по совпадению пробега/даты) или `in\_stock`.

&#x20;  - На основе строки 10 (`Шины летние Hankook Tire Ventus V12 evo2 K120 195/55 R15 85V`, февраль 2020) создать карточку летнего комплекта шин в `tireSets` (`manufactureYear: 2020`, `recommendedMaxAgeYears: 6`).

4\. \*\*Регламент ТО (`Календарь замены`, 9 узлов) и Разное (`Разное`, 49 строк):\*\*

&#x20;  - Перенести все 9 узлов с интервалами по пробегу (`intervalKm`) и дням (`intervalDays`).

&#x20;  - Вывести в терминал отчёт о стопроцентном совпадении контрольных сумм с листом «Общее».
