\# AGENTS.md — Правила агентной разработки проекта «Автокалендарь PWA»



\## 1. Главный принцип: Модульная разработка по спецификациям (Spec-Driven)

Ты разрабатываешь Local-First PWA приложение для учёта автомобилей. Вся документация разбита на детальные файлы в папке `specs/`.

Тебе \*\*КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО\*\* писать всё приложение за один шаг или упрощать интерфейс.



\### Золотые правила качества кода и UI:

1\. \*\*Один шаг — один файл спецификации:\*\* Перед созданием или редактированием любого экрана ты обязан полностью прочитать соответствующий файл в `specs/0X\_SCREEN\_\*.md` и реализовать \*\*каждый\*\* описанный там элемент, формулу, бейдж, фильтр и обработчик клика.

2\. \*\*Никаких заглушек:\*\* Запрещены комментарии `// TODO`, пустые функции, фейковые (захардкоженные) цифры вместо реальных расчётов из базы `IndexedDB` или пропуск модальных окон.

3\. \*\*Реактивность и связность:\*\* Добавление заправки, сервиса или запчасти должно мгновенно обновлять глобальный пробег автомобиля, пересчитывать остатки до ТО, обновлять сезонный пробег текущих шин и менять цифры на Главной странице без перезагрузки.

4\. \*\*Поддержка Дневной и Ночной темы (Light / Dark Mode):\*\* Используй Tailwind CSS с классом `dark` на корневом `<html>`. Все экраны должны иметь продуманные цвета как для светлой темы (`bg-slate-50`, карточки `bg-white`, текст `text-slate-900`), так и для тёмной темы (`dark:bg-slate-950`, карточки `dark:bg-slate-900`, текст `dark:text-slate-100`).

5\. \*\*Безопасность личных данных в Git:\*\* Файл `Автокалендарь.xlsx` и сгенерированный конвертером `autocalendar\_initial\_backup.json` содержат личные данные. Они должны быть в `.gitignore` и никогда не попадать в коммиты для GitHub.

\## 6. Технические нюансы сборки и деплоя (Обязательно к выполнению!)



1\. \*\*Правильный `base` в `vite.config.ts` и PWA Manifest для GitHub Pages:\*\*

&#x20;  - На GitHub Pages сайт открывается в подпапке `https://<user>.github.io/<repo>/`.

&#x20;  - Если оставить `base: '/'`, после деплоя будет белый экран (ошибка 404 на JS/CSS файлах).

&#x20;  - Обязательно настрой в `vite.config.ts`: `base: './'` (или динамически от имени репозитория), а в настройках `VitePWA` укажи `scope: './'` и `start\_url: './'`.

2\. \*\*Роутинг без ошибки 404 при обновлении страницы:\*\*

&#x20;  - GitHub Pages — это статический хостинг, он не умеет перенаправлять `/refuelings` на `index.html`.

&#x20;  - Поэтому для переключения вкладок используй \*\*либо `createWebHashHistory()` (Hash-роутинг вида `#/refuelings`)\*\*, либо реактивное переключение активного экрана через стейт приложения (`currentTab`), чтобы при перезагрузке страницы никогда не возникала ошибка 404.

3\. \*\*Защита от удаления базы браузером (`navigator.storage.persist()`):\*\*

&#x20;  - Мобильные браузеры могут очищать `IndexedDB`, если на телефоне мало места.

&#x20;  - При старте приложения (`App.vue` / `App.tsx`) обязательно вызывай:

&#x20;    `if (navigator.storage \&\& navigator.storage.persist) { navigator.storage.persist(); }` — это переводит локальную базу данных PWA в статус постоянного нестираемого хранилища на Android.

4\. \*\*Генерация валидных PNG-иконок для установки PWA на Android:\*\*

&#x20;  - Chrome на Android \*\*НЕ покажет\*\* кнопку «Установить приложение» (WebAPK), если в `manifest.webmanifest` указана только SVG-иконка или битые ссылки на картинки.

&#x20;  - Напиши микро-скрипт на Python (`Pillow` или встроенный генератор PNG) на Фазе 2, который физически создаст в папке `public/` валидные файлы `pwa-192x192.png` и `pwa-512x512.png` с красивой иконкой автомобиля.

5\. \*\*Точка и запятая при вводе дробных чисел с телефона:\*\*

&#x20;  - На русской клавиатуре Android в цифровой раскладке иногда вводится запятая `,` вместо точки `.` (например, `43,06` л или `65,53` ₽).

&#x20;  - Все функции парсинга числовых инпутов обязаны предварительно делать `.replace(',', '.')`, чтобы не возникало `NaN`.

## 7. Проверки пользователем

Все интерактивные проверки приложения и скриншоты выполняет пользователь самостоятельно. Не перехватывать управление браузером и не нажимать элементы интерфейса, если пользователь отдельно не попросил об этом. После каждого изменения давать пользователю короткую пошаговую инструкцию для проверки и список ожидаемых результатов. Агент самостоятельно выполняет только статический анализ кода, TypeScript-проверку и сборку проекта.
